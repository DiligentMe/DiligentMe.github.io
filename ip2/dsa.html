PART 1

Searching Algorithms

Searching means locating a target value inside a collection of data. The choice of algorithm depends heavily on whether the data is sorted.

LINEAR SEARCH

Check one element at a time

Linear Search starts from the beginning and compares each element with the target until a match is found or the list ends. It works on sorted or unsorted data.

292
33
184

Target = 18 → compare 14, 7, 29, 3, then 18.

Think of it like: Finding a particular notebook in an unorganized pile by checking each notebook. 
int linearSearch(int a[], int n, int key) {
    for (int i = 0; i < n; i++) {
        if (a[i] == key)
            return i;
    }
    return -1;
}

Time: Best O(1), Average O(n), Worst O(n)   •   Space: O(1)

BINARY SEARCH

Repeatedly cut the search space in half

Binary Search compares the target with the middle element. One half of the data can then be ignored. The important condition is that the data must already be sorted. 

int binarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;

        if (a[mid] == key) return mid;
        if (a[mid] < key)  low = mid + 1;
        else                high = mid - 1;
    }
    return -1;
}

Time: Best O(1), Average/Worst O(log n)   •   Space: O(1) iterative

Exam point: Binary Search is faster asymptotically, but it cannot directly be used on an unsorted array. If you sort only to perform one small search, the cost of sorting may be more than a simple Linear Search.
PART 2

Sorting Algorithms

Sorting arranges data in a meaningful order—usually ascending or descending. Sorted data is easier to search, display, compare and process.

BUBBLE SORT

Swap neighboring elements

Compare adjacent values. If they are in the wrong order, swap them. After each pass, a large value “bubbles” toward the end.

5
1

8 > 3 → swap → 3, 8, 5, 1

Best: O(n)*   Avg/Worst: O(n²)   Stable: Yes

*Best O(n) with an optimized “no swaps” check.

SELECTION SORT

Select the minimum

Find the smallest element in the unsorted part and place it at the beginning. Repeat for the remaining positions.

1

Minimum = 1 → move/swap it into the first position.

Best/Avg/Worst: O(n²)   Stable: Usually No   Swaps: Few

INSERTION SORT

Insert into the sorted portion

Build a sorted portion from left to right. Take the next value and insert it into its correct place—similar to arranging playing cards.

5

Insert 5 between 3 and 7.

Best: O(n)   Avg/Worst: O(n²)   Stable: Yes

MERGE SORT

Divide, sort, merge

Split the array into halves until single elements remain, then merge the pieces back together in sorted order.

Best/Avg/Worst: O(n log n)   Stable: Yes   Extra space: O(n)

QUICK SORT

Partition around a pivot

Choose a pivot, put smaller values on one side and larger values on the other, then recursively sort the partitions.

Best/Avg: O(n log n)   Worst: O(n²)   In-place: Commonly Yes

WHY SORT?

Sorting is often a preparation step

Once data is sorted, many later operations become easier: Binary Search, duplicate detection, range queries, median computation and ordered reporting.

A good algorithm is not simply the one with the smallest Big-O. Consider input size, memory, ordering, stability and whether data is already nearly sorted.

C implementations of three basic sorts

// Bubble Sort
for (int i = 0; i < n-1; i++) {
    int swapped = 0;
    for (int j = 0; j < n-i-1; j++) {
        if (a[j] > a[j+1]) {
            int t = a[j];
            a[j] = a[j+1];
            a[j+1] = t;
            swapped = 1;
        }
    }
    if (!swapped) break;
}
// Selection Sort
for (int i = 0; i < n-1; i++) {
    int min = i;
    for (int j = i+1; j < n; j++) {
        if (a[j] < a[min])
            min = j;
    }
    int t = a[i];
    a[i] = a[min];
    a[min] = t;
}
// Insertion Sort
for (int i = 1; i < n; i++) {
    int key = a[i];
    int j = i - 1;

    while (j >= 0 && a[j] > key) {
        a[j+1] = a[j];
        j--;
    }
    a[j+1] = key;
}

Stability and in-place sorting

Stable sort: equal-valued records keep their original relative order.

In-place sort: uses very little extra memory beyond the original array.

Example: If students are first ordered by name and then stably sorted by marks, students with equal marks can retain their previous name ordering.

Questions to discuss in class

Why is Binary Search O(log n)?

Because every comparison removes about half of the remaining search space. The number of halvings required to reduce n elements to one grows logarithmically.

When can Linear Search be a reasonable choice?

When the data is small, unsorted, searched only once, or when sorting would add unnecessary overhead.

Why can Insertion Sort be good for nearly sorted data?

Each new element usually needs only a small number of shifts, so its behavior can approach linear time when the array is already close to sorted.

Why does Merge Sort need extra memory?

The merge step commonly uses temporary storage to combine two sorted subarrays into one sorted sequence.

Why can Quick Sort become O(n²)?

If pivot choices repeatedly produce highly unbalanced partitions—for example, one partition of size n−1 and another of size 0—the recursion behaves poorly.

Programming exercises

  1. Write Linear Search and count how many comparisons are made before finding the key.
  2. Write Binary Search and display low, mid, and high after every iteration.
  3. Modify Bubble Sort so that it stops early when no swap happens in a pass.
  4. Sort an array using Selection Sort and count the number of swaps.
  5. Use Insertion Sort on an already sorted array. Compare the number of operations with a reverse-sorted array.
  6. Given a sorted array with duplicates, modify Binary Search to find the first occurrence of a target.
  7. Compare Bubble Sort and Merge Sort for 10, 100, 1,000 and 10,000 elements. Record execution time.
